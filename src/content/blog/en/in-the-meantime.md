At this stage of my learning I am working on two projects that are quite different from each other, but that complement each other a lot in everything I am learning.

One is a group project for a construction company and the other is a much more ambitious personal project: an **online course SaaS** that I am building on my own.

Working on both at the same time is letting me see two very different realities of development: collaborating with other developers, and building a complete system by myself.

---

## 👷‍♀️ Group project: management system for a construction company

On the group project we are developing an **internal management system for a construction company**.

The idea is to build a web application that makes it possible to manage different aspects of the daily work of the site workers and the admin team.

The system has different **user roles**:

- 👨‍💼 Administrator
- 👷 Site worker

Each one has different permissions and features within the application.

The main features include:

- 📋 site management
- 👷 worker management
- 🔔 internal notifications
- 📸 uploading photos from site
- 🧭 different panels depending on the user's role

### 🧰 Technologies in the project

- **Frontend:** Angular
- **Backend:** Python + FastAPI
- **Database:** SQL
- **Deploy:** Railway

In my case I am working especially on:

- 🎨 developing the **frontend in Angular**
- 🔗 preparing the **integration with the backend**
- 🧠 designing some of the **application flows**

Something interesting about this project is that we are starting by developing the **frontend without connecting the whole backend yet**, which lets us move faster on the structure of the application.

This is teaching me several important things:

- 🏗️ thinking about the **architecture of an application**
- 🧩 separating responsibilities between frontend and backend
- 🔐 working with **roles and permissions**
- 👥 designing interfaces built for **real users**

I am also learning something fundamental: **working in a team**.
When you develop with other people you have to communicate decisions, organise tasks and think about how the parts each person builds fit together.

---

## 🚀 Personal project: building an online course SaaS

In parallel I am developing a much bigger personal project: an **online course SaaS**.

The idea is to build a platform where instructors can create courses and students can consume them, with a complete system for authentication, course management and content.

### 🧰 Project stack

- **Frontend:** Angular
- **Backend:** FastAPI
- **Database:** PostgreSQL on Supabase
- **UI:** PrimeNG

Here I am working on absolutely **every part of the system**:

- 🗄️ database design
- ⚙️ backend architecture
- 🔐 authentication with JWT
- 🌐 API endpoints
- 🧱 frontend structure
- 🧩 components and services
- 🔗 connection between frontend and backend

Building something like this forces you to understand how the whole system works **end to end**.

And of course… a lot of errors show up along the way.

In fact, one of the things I am learning most in this project is **backend debugging**.

I have run into some quite interesting problems, such as:

- 🔄 differences between **Pydantic models and SQLAlchemy models**
- 🆔 conflicts between **UUID vs Integer in PostgreSQL**
- ⚡ problems with **PgBouncer and asyncpg**
- 📦 errors caused by badly structured modules or imports
- 🕒 problems with **datetime and timezone**
- 🛑 role validations failing because of constraints in the database

They are the kind of errors that look impossible at first, but when you finally understand them… you learn a huge amount about how the tools really work.

---

## 🧠 What I am learning by working on both projects

Working on these two projects at the same time is teaching me something important:

**programming is not just writing code.**

It is also:

- 🏗️ designing systems
- 🗄️ understanding databases
- 🧭 thinking about architecture
- 🐞 solving complex errors
- 📝 documenting
- 👥 thinking about users
- 📚 constantly learning new tools

I am also starting to use AI tools like **ChatGPT or Claude** as assistants to analyse problems, review code or structure ideas. Used well, they become a very powerful tool for learning faster.

---

## 🌱 Building while learning

Something I try to do is not to stay stuck in tutorials or small exercises.

I prefer to build **real projects**, even imperfect ones, because that is where the interesting problems actually appear.

It is when you have to connect **frontend, backend, database, authentication and deployment** that you start to understand how everything works.

There is still an enormous amount to learn, but these projects are becoming a kind of laboratory where I can try out ideas, get things wrong, fix them and keep improving.

And in the end, I think that is one of the best ways to learn to program.
